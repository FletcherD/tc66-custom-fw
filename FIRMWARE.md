# Firmware internals

How the firmware (`rust/`) is put together, the hard-won gotchas, and the
build/flash/debug workflow. Read `HARDWARE.md` first for the board facts
(memory map, pins, peripherals, command protocol, calibration model).

Exactly one interrupt runs: **USBD_LP (IRQ 37)** services the USB peripheral
(so host traffic never waits on blocking main-loop work). Everything else is
polled from the main loop: the TIMER5-paced sampler, command dispatch and
reply building, energy integration, and the UI. All other IRQs stay masked
from reset onward (`__pre_init`), and PRIMASK stays set until `main()`
finishes initializing every static the ISR touches. See "USB" below for the
ISR/thread split and the soundness rules for shared state.

## Module map (`rust/src/`)

| `board.rs` | 48 MHz clock bring-up, PA9 D+ soft-connect choreography |
| `usb_bus.rs` | stm32-usbd `UsbPeripheral` impl for the GD32 USBD |
| `flasher.rs` | `updat` self-flasher (`.flasher` section, runs from SRAM) |
| `i2c.rs` | polled I2C0 master (INA226 + EEPROM bus), `i2crd` dev verb backend |
| `ina.rs` | INA226 reads, EEPROM calibration, timer-paced `Sampler`, NTC/D± conversion |
| `adc.rs` | polled on-chip ADC (NTC, D+/D−), `adcrd` dev verb backend |

## Startup / linker

**`cortex-m-rt` 0.7** provides `.data`/`.bss` init and the reset handler; the
**gd32f1 PAC's `rt` feature** (which enables `cortex-m-rt/device`) provides
the device vector table so `#[interrupt] fn USBD_LP()` lands in slot 37 —
every other IRQ entry PROVIDEs to our `DefaultHandler`. Board specifics:

- `memory.x`: `FLASH ORIGIN 0x08002C00 LENGTH 51840` (the exact flashable image
  size, so the linker fails before the pad step would) and `RAM LENGTH 0xE40` —
  RAM deliberately *ends* at `0x20000e40`, which both makes `_stack_start` the
  known-good SP (top-of-RAM faults the bootloader hand-off) and fences
  statics/stack below the marker window (0x20001000+) and flasher SRAM
  (0x20001400+) by construction.
- The **`set-sp` cargo feature** loads MSP from `_stack_start` first thing;
  **`set-vtor` stays OFF** on purpose: VTOR is set inside our own `global_asm!`
  **`__pre_init`** (`startup.rs`) *after* `cpsid i` — with interrupts still
  live, a bootloader-armed pending IRQ must vector through the bootloader's
  valid table, not into our spinning DefaultHandler. `__pre_init` also
  masks+clears all NVIC IRQs (ICER0/1, ICPR0/1; the bootloader can leave the
  USBD IRQ enabled+pending). PRIMASK stays set until late in `main()`, which
  unmasks **only** USBD_LP once the ISR's statics are initialized (see USB).
  The `#[pre_init]` attribute is deprecated; a strong `__pre_init` asm symbol
  is the sanctioned hook.
- `DefaultHandler` is overridden in `global_asm!` (not `#[exception]`) so the
  stacked-PC capture reads the hardware frame at MSP; `HardFault` uses
  `#[exception]` + `ExceptionFrame`. Both write fixed SRAM capture windows —
  `markers.rs` has the full map.

### Boot-path gotchas (cost real debugging time — do not rediscover)

1. **Initial SP must be `0x20000e40`**, not top-of-RAM `0x20002000` — the exact
   top faults the bootloader's hand-off (BFAR reads `0x20002000`).
2. **Set `VTOR = 0x08002c00` early** — the bootloader jumps to the app without
   setting it.
3. **PA9 is the USB D+ soft-connect** (no internal pull-up on this USBD; PA9
   drives D+ through a resistor). The bootloader hands off with the bus still
   connected, so the app must drive **PA9 low → bring USB up → PA9 high** or
   the host never re-enumerates it (device inits fine, ISTR/FNR stay 0).
4. **Complete vector table + clear NVIC at reset** — an unhandled IRQ vectors
   into `.text` → wild branch → lockup. cortex-m-rt supplies the table;
   `__pre_init` clears NVIC.

## Register access

The **`gd32f1` PAC** (gd32-rust project; features `gd32f150` +
`critical-section`), GD32-native field names. `Peripherals::take()` in main
(cortex-m `critical-section-single-core`); the static contexts with no
peripheral handle (`UsbPeripheral::enable()`, the `updat` EP scan) use
`pac::X::ptr()` like the STM32 HALs do. Two places stay raw-pointer on purpose:
`markers.rs` (fixed SRAM addresses, not a peripheral) and the `.flasher`
section (must stay self-contained, below).

## USB

The ecosystem stack: **`usb-device` 0.3 + `usbd-serial` 0.2 + `stm32-usbd`
0.8**. `usb_bus.rs` implements `UsbPeripheral` with raw pointers (registers
`0x40005C00`, PMA `0x40006000`, 512 B, `MemoryAccess::Word16x1` = the
doubled-PMA model; `DP_PULL_UP_FEATURE = false`). `board.rs` does the PA9
low → `build()` → PA9 high choreography — no USB stack does the soft-connect
for you. Device identity (VID/PID/strings/bcdDevice) is set via
`UsbDeviceBuilder`; endpoint layout is whatever the stack allocates (today:
EP1 = interrupt IN 0x81, EP2 = bulk OUT 0x02 + bulk IN 0x82 — differs from the
stock EP map, which no host tool cares about since they bind the CDC class).
usbd-serial terminates transfers with a short packet, so the 192-B `getva`
arrives in one read (the stock firmware's stuck-last-block cdc_acm quirk does
not exist here).

**Never write a data endpoint before the first bus reset has been
processed.** An `ep_in.write` before that lands in an EPnR whose endpoint-
address field is still 0 — a second endpoint-0 claimant that corrupts EP0
control transfers (enumeration wedges on the config-descriptor read with
host-side -110 timeouts; cost a K1 recovery to find, builds 36–38). In the
ISR architecture this holds by construction: the ISR only runs on USB
events, and any reset is processed by `dev.poll` (which programs the EPnR
address fields) before `poll_cmd`/`arm` touch an endpoint. The grace window
serves only CDC (no powerz endpoint writes). Keep it that way.

### The grace window (pseudo-bootloader)

The first ~10 s after the IRQ unmask dispatch ONLY `query`→`firm` and
`updat` — no TFT, sampler, I2C/ADC, or full command set. USB runs on the
same ISR + ring machinery as normal operation (one code path; the thread
does nothing but drain the ring, so the ring-full livelock below cannot
occur here). A fault in any feature that starts later is recovered by
power-cycling and running `make flash` inside the window (no K1; escape
drill bench-verified). `MK_PROBE` reads `0x6ACE6ACE` while the window is
open. Standalone (no host) boots just wait out the 10 s. If the ISR/ring
machinery itself is ever broken, the window cannot save you — that is what
K1 recovery remains for.

### Interrupt-driven servicing (the USBD_LP ISR)

USB is serviced from **`USBD_LP` (IRQ 37)** — the
only unmasked interrupt — so blocking main-loop work (an ADC burst ~1 ms,
TFT draws, getva's ~20 ms AES) can never starve the bus; the powerz
driver's 5 ms URB budget is met regardless of what the loop is doing.
stm32-usbd's `enable()` sets the CNTR masks (CTRM/RESETM/SUSPM/WKUPM — no
SOF, so the ISR is event-driven); `main()` publishes the USB object
pointers, unmasks USBD_LP in the NVIC, and clears PRIMASK as its last init
step. The split:

- **ISR** (short, bounded): `dev.poll` (control pipe + endpoint callbacks),
  powerz `poll_cmd`/`arm` (`endpoint_in_complete` re-arms the pre-built ADC
  reply inside the poll), then drains complete CDC packets into `CMD_RING`
  (reading straight into the ring slot — no scratch buffer). Phase markers
  in the MK_USB block locate a wedge (markers.rs).
- **Thread mode** (main loop): pops `CMD_RING`, dispatches commands and
  builds replies (AES etc.) with interrupts enabled, then feeds the bytes to
  usbd-serial under **short critical sections** (`with_usb`) — one buffer
  copy or endpoint write each, never held across slow work. `serial.write`
  kicks the first packet itself; the ISR's `endpoint_in_complete` flush
  drains the rest.

Shared-state soundness (full arguments live next to each item in the code):

| Item | Rule |
|---|---|
| `UsbPtrs` (dev/pz/serial) | one ownership unit in `main`'s frame (main never returns); ISR derives `&mut`s freely (single IRQ, no nesting), thread mode only inside `with_usb` (PRIMASK) — the two contexts are mutually exclusive, and main's locals are shadowed after publishing |
| `CMD_RING` | SPSC slot ring; producer (`drain_serial`) runs in the ISR *or* under `interrupt::free`, consumer only in the thread loop; head/tail are single-word atomics with acquire/release pairing; on a full ring the ISR PARKS ITSELF (NVIC mask) — leaving the packet unread keeps the level-triggered CTR asserted and would refire the IRQ forever, starving the thread that must drain the ring (bench-hit livelock: 2.3M IRQs, thread frozen); the thread unmasks after popping a slot, and slots are copied out before dispatch so the ISR stays live during slow replies |
| `powerz::REPLY` (52 B) | multi-word, but only reachable through `PowerZ` methods, which are only reachable via the mutually-exclusive contexts above — `set_payload` (thread, in CS) can never tear an `arm` read (ISR) |
| `PUBLISHED` (`Meas`) | thread-mode only — the ISR's data comes from `REPLY`, refreshed once per 4 ms tick |
| markers | single-word volatile writes (naturally atomic on M3); every counter has a single writer context (see markers.rs) |

`updat` freezes the world before the flasher handoff: `cpsid i` + NVIC-mask
USBD_LP, *then* `find_bulk_ep()` + `flasher::launch` — nothing can touch
endpoint state between discovery and the SRAM takeover (and the erase can
never be interrupted). On a refused `updat` (no bulk EP) both are restored.

Keep the ISR shallow: its whole call subtree is charged on top of the
thread-mode worst case by the stack gate (below), and headroom is thin.

Two clone quirks the design absorbs (both bench-measured): sustained NAK
traffic stalls CPU APB/USBD accesses ~1-5 ms each (hence the SysTick — core-
internal — timebase, and why the polled architecture could not reliably meet
the 5 ms budget under gap-free host polling), and endpoint completion
callbacks are silently dropped ~20-30% of the time (hence `arm()` writes
unconditionally — WouldBlock is the cheap no-op — and never trusts a
software armed-latch).

Build profile stays `opt-level = 1`, `lto = false`, `codegen-units = 1`: the
original C reference had an unexplained post-enumeration lockup when the USB
path was aggressively inlined at `-Os`; revisit optimization only as an
isolated, revertable change. One such change exists:
`[profile.release.package.aes] opt-level = 3` — pure-compute crypto with no
USB-path code; at opt-level 1 the fixsliced AES made every getva reply cost
~64 ms of main-loop blocking (bench-measured; see Measurement below).

## `updat` self-flasher

`flasher.rs`: `flasher_main` lives in a dedicated `.flasher` section **linked
to run at `0x20001400`** (VMA in `FLASHER_RAM`, see `memory.x` + `flasher.x`)
with its load image in flash; `launch()` copies it to SRAM and calls it via a
forced register-indirect jump. Being linked at its run address means no
position-independence tricks. It discovers the bulk endpoint's PMA buffers
**from the BTABLE at runtime** (the EP index is found by scanning EPnR for the
bulk type), so it tracks whatever the USB stack allocated.

Constraints inside `.flasher` — it erases the app region it was loaded from,
so after the erase any reference into app flash is fatal: raw pointers only,
no panicking ops (`MaybeUninit` buffer — a zeroed array could emit a memclr
call into flash), its own `asm!` for cpsid/dsb, bootloader flash routines
called through `transmute`d fn pointers (`blx reg`; addresses in HARDWARE.md).
**`make flasher-gate`** (part of every build) disassembles the section and
fails if any literal references app flash or any call leaves the section.

Protocol: erase → `uprdy` → 810 × (recv 64 B → program → `OK`) → AIRCR reset;
`tools/app_update.py` is the host side.

**Linker-script trap (cost one K1 recovery):** the section is injected with
`INSERT AFTER .uninit` — NOT `.data`. cortex-m-rt deliberately extends its
`__sdata..__edata` Reset-copy range around sections inserted after `.data` (a
documented mechanism that assumes a *contiguous* VMA); with our disjoint VMA
that made Reset smear ~6 KB of flash over all of low RAM every boot — invisible
with zero statics, fatal the day the PAC's `DEVICE_PERIPHERALS` flag appeared.
Two guards now exist: `memory.x` pins `_stack_end`/`__sheap` (a definition must
come *before* link.x's `PROVIDE` to suppress it under rust-lld — hence
memory.x, not flasher.x), and **`make init-gate`** asserts
`__sdata/__edata/__sbss/__ebss` all lie inside real RAM on every build.

**Stack budget (`make stack-gate`, tools/stack_gate.py).** The stack is small
and main()'s frame alone is ~2 KB, and a boot-path overflow hardfaults
*before* the D+ pull-up — an invisible dead board needing K1 recovery (this
shipped once, as build 35). The gate computes a conservative static
worst-case stack depth (disassembly call graph; multi-path frames and tail
calls overestimated; `blx rN` trait dispatch charged the max UsbClass-impl
subtree; recursion is a hard error). Because the USBD_LP ISR runs real code,
the gate discovers every handler from the `.vector_table` section and checks
**two phases** against `STACK_TOP − __ebss` (+192 B margin):
*boot* (PRIMASK set: thread worst + one exception frame + the fault-handler
chain) and *run* (USBD unmasked: thread worst **with pre-unmask-only chains
pruned** + exception frame + the deepest IRQ-handler chain + a second
exception frame + the fault chain — single IRQ, no nesting, faults spin).
The pruned chains are `PRE_IRQ_ROOTS` in stack_gate.py (today: `getva::init`);
the gate verifies each is called exactly once from the main body and is
unreachable from any handler, but *the call staying before `NVIC::unmask` is
a code invariant* — keep it that way (comments at the call site).
Related subtleties, all load-bearing:
- **The runtime stack top (0x20001000) is raised in `__pre_init`**
  (startup.rs), not in the linker: the flash header's initial SP must stay
  at the bootloader-proven `0x20000E40` (the bootloader faults on some SP
  values — 0x20002000 known bad, predicate unknown). `STACK_TOP` in
  stack_gate.py must match the asm constant.
- **Deep one-shot work runs at boot, not under the deepest chain**: the AES
  key schedule (~1.1 KB of chain) runs once from `getva::init()` before the
  main loop *and before the USBD unmask* (which is what lets the gate prune
  it from the run phase); `build()` only reads the cached cipher. Keep new
  expensive init work on that pattern, and never put a call cycle in the
  graph (the tft `fill_rect`/`ensure_init` cycle was broken with
  `fill_rect_raw` for exactly this).

## Measurement (M1)

- `i2c.rs`: polled I2C0 master (PB6/PB7 AF1, 100 kHz, the F1-style IP's AN2824
  receive sequences), bounded waits with stage+STAT0/STAT1 error snapshots,
  SRESET + reconfigure per transaction (stateless, self-healing).
- `ina.rs`: INA226 register reads (big-endian), EEPROM calibration constants
  (LE u32 at 0x2004/44/08/0c/58), the calibration formulas from HARDWARE.md,
  and `Sampler` — one I2C read per 4 ms tick, 8 bus + 16 shunt reads per
  window, then one ADC tick (NTC + D+ + D−) → publish at ~10.4 Hz (250/24).
  Failures bump MK_I2CERR and restart the window; cal load retries.
  **The tick timebase is TIMER5** free-running at 10 kHz (no pins, no IRQ):
  the main loop accrues elapsed ticks from CNT deltas (40 counts = 1 tick),
  so time spent blocked — a getva reply is ~20 ms of soft AES — is caught up
  with back-to-back ticks instead of lost. (SysTick's COUNTFLAG latches only
  one wrap: with it, hammering getva stalled the sampler to ~0.65 Hz and
  slowed the energy clock ~16×. Verified fixed on the bench: flat-out getva
  polling now costs 0% window rate.) The 16-bit counter wraps at 6.55 s,
  far beyond the longest blocking path (write_all's absent-host budget).
  **The explicit INA226 config write (0x4127) at sampler start is
  load-bearing** — the chip returns 0 for bus voltage until (re)configured.
- `adc.rs`: polled on-chip ADC — **enable IRC14M first** (the ADC's dedicated
  clock, off at reset; calibration hangs without it), ADCON set alone, CLB
  calibration, SWRCST software trigger, 239.5-cycle sampling. NTC uses the
  recovered stock β-model on ch1 (this unit); channels + model in HARDWARE.md.
- Energy: 1 Hz integration in the main loop off the same tick stream (250
  ticks = 1 s) — RAM-only, zeroed at boot, both getva groups publish the same
  value. Persistence = M2.
- `getva.rs`: template + live-field patch + CRC16/MODBUS + AES-256-ECB.
  Stamps the sampler window counter (MK_WINDOWS) at offset 132 (pac3+4, a
  stock-unused field). The AES key schedule is cached in a static after the
  first reply and blocks are encrypted as one batch (the fixsliced core works
  on block pairs) — with the per-crate `opt-level = 3` on `aes` (Cargo.toml)
  this takes a reply from ~64 ms to ~20 ms. Also builds the **`rawva`** dev
  verb reply (`build_raw`): the same fields plaintext + CRC16, 46 B, ~1 ms —
  the streaming endpoint. Host recipe + layout: HARDWARE.md, `tools/rawva.py`
  (bench-verified: 700 polls/s, zero missed windows, sampler unaffected).
- `tft.rs`: the recovered stock ST7735S path (TFT_FINDINGS.md in the RE repo)
  on hardware SPI0 at 24 MHz — init sequence verbatim, CASET/RASET with the
  panel's +1/+26 GRAM offset, `fill_rect` streaming straight into GRAM (no
  framebuffer). **MADCTL is `0xA8`** — stock's "180° flip" variant is right-side
  up on this unit; `0x68` is upside-down (verified by webcam). DC is only
  flipped after `TRANS` reads idle (TBE alone means the shifter may still be
  busy). Backlight: PA9 enable is already high (it doubles as the USB D+
  soft-connect), brightness = TIMER1 CH1 PWM on PB3 (1 kHz, compare 0..=999,
  init 499). Verbs: `tftfl` = test pattern / solid fill, `tftbl` = brightness,
  `tftui` = force a screen refresh (host side: `tools/tft.py`).
  **Screen idle timeout**: 10 min with no measurable input (V ≤ 2.5 V and
  I ≤ 1 mA) blanks the panel — DISPOFF (source outputs parked, so no static
  image is driven into the liquid crystal; an overnight static screen caused
  real image persistence) plus backlight off. Wakes within 1 s of activity;
  the tft dev verbs also wake it. GRAM writes still work while blanked, so
  ui::draw keeps running and content is current at wake.
- The main screen (`ui.rs` + `font.rs`): three 8-cell lines — V yellow,
  I cyan, P green — at fixed monospace cell positions (18×24 px). Cells are
  always fully overdrawn fg/bg (no clear → no flicker) and only redrawn when
  their character changes, so the idle 2 Hz refresh in the main loop draws
  nothing. TFT init + first frame run at boot **before `pa9_high`** — the
  init's ~400 ms of delays must not stall USB enumeration. A failed draw
  disables the always-on refresh for that boot (`tft_alive`), keeping a
  wedged SPI from slowing the loop; the dev verbs can still retry.
- Fonts are generated offline: `tools/mkfont.py <font> <px> <chars> <out.rs>`
  rasterizes a TTF/OTF (Pillow) into 1-bpp cell bitmaps. The current font is
  u8g2's Inconsolata Bold source (`tools/font/ttf/inb.otf` in the u8g2 repo,
  SIL OFL) at size 30 → 18×24 cells, subset `0123456789 .-VAW`, 1.2 KB.
- `getva.rs`: patches all live fields (V/I/P/R, mAh/mWh, temp+sign, D±) into
  the decrypted known-good template, recomputes **CRC16/MODBUS over bytes
  0..60 of each 64-B block** (stored LE at 60..64), AES-256-ECB encrypts
  on-device (`aes` crate). Serial/run-count still carry template values (M2).

## Build / flash / debug workflow

All wrapped in `rust/Makefile`:

- `make flash` — build → gates (below) → objcopy → pad to 51840 B → hands-free
  flash via the running app's `updat` (`tools/app_update.py`).
- `make recover` — AES image + `tools/flash_image.py` (hold K1 while plugging
  in first). Recovery always works: the bootloader is never written.
- `make markers` — non-halting SRAM marker read via openocd (`openocd.cfg` at
  the repo root; Pico debugprobe wiring in HARDWARE.md).
- Build gates, run on every build: **flasher-gate** (`.flasher` is
  self-contained), **init-gate** (data/bss init symbols inside real RAM),
  **header gate** (SP = 0x20000e40, reset vector Thumb + in-slot, size fits).

Bump `BUILD_ID` in `main.rs` when flashing; reading `MK_BUILD` (0x20001060)
back proves the new image is actually running.

### The debug reality (the chip is readout-protected)

- **SWD `halt`/`reset`/`step` lock the core up**, and even a background `mdw`
  read often leaves it halted — a "frozen" SRAM value does NOT mean the app is
  dead. **Verify liveness over serial** (`query`→`firm`), no debugger attached.
- Background SRAM reads work while the core runs: debug via the **SRAM marker
  map** (`markers.rs`) + `make markers`.
- If serial goes quiet after a markers read, **power-cycle the meter's hub
  port** (the `usb-hub-power` skill; the meter is on port b2) and it comes back.
- `probe-rs`/`defmt`/RTT are **not usable** (they need halt). Flash via
  `updat`/bootloader, debug via markers + serial + the `i2crd`/`adcrd` dev verbs.

### Dev-verb pattern for new peripherals

Bring up new hardware behind a host-triggered dev verb first (`i2crd`,
`adcrd`): nothing runs at boot, every wait is bounded, errors return staged
diagnostics to the host. A fault is then always recoverable by power-cycle,
and the boot/updat path stays safe. Only move the feature into the always-on
path (timer/sampler) once it's proven.
