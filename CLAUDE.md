# CLAUDE.md

Custom Rust firmware for the RuiDeng TC66/TC66C USB-C power meter, developed
against real hardware on the bench. M0 (self-hosting USB + self-reflash),
M1 (real calibrated measurement), and the M3 basics (ST7735S driver in
tft.rs + always-on V/I/P screen with 15 s idle screen-off) are done. Pixel
streaming is DMA-driven and non-blocking (tft.rs engine on DMA ch2, pumped
by ui::service from the main loop — no display interrupt). USB
is ISR-serviced and the device is a composite that emulates a POWER-Z
KM003C (mainline Linux `powerz` hwmon binds it) — **powerz comms are the
priority path; getva/CDC exists for compatibility**. The sampler runs from
the TIMER5 interrupt (250 Hz, interleaved INA226 reads — ina.rs), immune
to main-loop blocking. The hot path is pinned below the GD32's 32 KB
zero-wait flash boundary (`rust/fast.x` + `make fast-gate` — FIRMWARE.md
"Fast-flash placement"; query 0.2 / rawva 0.6 / getva 2.3 ms). Profile
with the on-device PC sampler (`pcprf` verb + tools/pcprofile.py; the DWT
is a stub — never trust PCSR). For lossless host streaming use the
plaintext `rawva` verb (window seq for dedup; tools/rawva.py); getva also
carries the seq at pac3+4. Next: M2 (persistence), the spi-dma refactor
branch (merge master into it first), the open QUIRKS.md investigations,
richer M3 screens. Fonts are generated by tools/mkfont.py; display
verification uses the bench webcam (see the memory notes). See README.md
for status/roadmap.

**The escape hatch**: the first ~10 s after every boot serve only
`query`/`updat` (grace window, MK_PROBE = 0x6ACE6ACE). If a build faults
after that window, power-cycle b2 and run `make flash` within ~10 s of
power-up — no K1 needed. K1 recovery is only for a broken grace
window/USB-core.

## Read these before working

- **HARDWARE.md** — board facts: memory map, bootloader contract, peripherals
  (INA226 @I²C 0x4A, EEPROM @0x50, FUSB302 @0x22, ADC channels/NTC model),
  command protocol, getva wire format, calibration formulas.
- **FIRMWARE.md** — firmware internals: module map, boot-path gotchas, the
  `.flasher` section mechanics, measurement pipeline, build gates, debug
  workflow. The gotchas there cost real debugging time — do not rediscover them.
- **QUIRKS.md** — measured GD32F150 misbehavior (USB event loss, NAK-traffic
  bus stalls, the no-thread-sweeps rule) + open investigations. Read it
  BEFORE changing anything in the USB service paths — several lines of
  main.rs exist only because of what is documented there.

## The development loop

```
cd rust && make flash      # build -> gates -> hands-free flash via updat (~1 s)
```
Then verify over serial: `query` → `firm`; `getva` → 192-B encrypted packet
(decrypt/parse snippets: HARDWARE.md). Bump `BUILD_ID` in `rust/src/main.rs`
each flash and read it back at marker 0x20001060 to prove the new image runs.
The board is on the bench hub, port **b2** — power-cycle it with the
`usb-hub-power` skill when needed. Host tools live in `tools/`.

## Hard rules

- **Never** write flash below `0x08002c00` or the config page at `0x0800fc00`.
  A bad app is always recoverable (K1 + `make recover` — needs the user to
  hold the physical button), but the bootloader/config must stay intact.
- **Never** use SWD `halt`/`reset`/`step` — the chip is readout-protected and
  halting wedges the core. Even `make markers` (background SRAM read) often
  leaves it halted: always follow with a serial liveness check, and
  power-cycle b2 if quiet. `probe-rs`/`defmt`/RTT do not work here.
- **EEPROM writes** (not implemented yet): the factory calibration lives
  there. `eeprom-backup.bin` (repo root) is this unit's verified factory
  image — keep it usable as a restore point.
- Bring up new hardware behind a **host-triggered dev verb** first (like
  `i2crd`/`adcrd`): nothing at boot, bounded waits, staged error replies.
  Move it into the always-on path only once proven. This keeps every failure
  recoverable by power-cycle instead of K1.
- Exactly two interrupts are unmasked, both at one NVIC priority (the
  stack-gate assumes no nesting): **USBD_LP services USB** (ISR/thread
  split, shared-state rules and the with_usb critical-section discipline:
  FIRMWARE.md "USB") and the **TIMER5 sampler tick** (ina.rs, unmasked late
  in `ina::start()`, after the grace window). Everything else stays masked
  and polled from the main loop; long work (AES, TFT) never runs in an ISR.
  All thread-mode I2C must run inside `ina::pause(...)`, and all thread-mode
  access to the published measurements goes through `ina::snapshot()`/its
  helpers — the soundness rules are the ina.rs module doc. Keep the build
  profile conservative (`opt-level = 1`, no LTO) — see FIRMWARE.md.
- The `.flasher` section must stay self-contained (no calls/literals into app
  flash); the `flasher-gate`/`init-gate`/`stack-gate` Makefile gates enforce
  this (and the static worst-case stack budget — a boot-path stack overflow
  bricks invisibly) and run on every build — never bypass them.

## Bench notes

- The meter is powered and reached via hub port b2; its measurement path
  (IN→OUT) is only live when something actually feeds the IN port — bus
  voltage/current legitimately read 0 otherwise.
- SWD (for `make markers`) is a Pico debugprobe; config is `openocd.cfg` at
  the repo root. Wiring in HARDWARE.md.
- Update the docs (README/HARDWARE/FIRMWARE) after functional changes — they
  describe the current state only; history lives in git.
